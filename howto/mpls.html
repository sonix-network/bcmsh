MPLS label switching

Trident 3 can push, swap and pop MPLS labels in hardware, and the MPLS module is initialised on a SONiC switch even though SONiC configures no MPLS of its own. This page builds a label-switched path in each direction between two switches by hand, using only the diag shell, and shows how to check it with counters. Each switch is the ingress router for one direction, where an IPv4 route pushes a label, and the penultimate router for the other, where the incoming label is popped (penultimate-hop popping, PHP) and the packet is sent on to the host as plain IPv4.

ce27 and ce29 are cabled to each other. The hosts use the switch’s router MAC as their gateway, as a static ARP entry (the chip does not answer ARP; see Building an L2 switch with VLANs and SVIs for giving the switch CPU an address).

Warning

Everything here is configured behind SONiC’s back. Use ports that SONiC does not use (no VLAN, port channel or IP address on them), VLAN IDs that SONiC does not use, and remove it all again when you are done (see Removing it again). A syncd restart also removes it.

1. The router MAC

An MPLS packet is only label-switched if its destination MAC is a station of the switch with MPLS termination allowed. SONiC’s router MAC already is one: it is the first entry in the station table, and its flags include MPLS:

Hardware-validated

drivshell> l2 station show ID=0x02000001
     SID=0x02000001, priority=0
     MAC=e0:39:d7:88:3b:0
     MAC MASK=ff:ff:ff:ff:ff:ff
     VLAN=0x0
     VLAN MASK=0x0
     SourcePort=0x0
     SourcePort MASK=0x0
     Flags=0x803c

Flags=0x803c is IPv4 (0x4), IPv6 (0x8), ARP (0x10), MPLS (0x20) and underlay (0x8000). The shell prints the MAC without the leading zero of each byte (3b:0 is 3b:00). Use this MAC on the L3 interfaces below, and as the next-hop MAC towards the other switch.

Note

A station added with l2 station add and MPLS=true but no VLAN did not make the switch accept labelled packets for that MAC, with or without a VLAN-scoped entry next to it. IPv4 routing to that MAC worked; labelled packets were flooded in the VLAN instead (see Troubleshooting). Use the router MAC.

2. VLANs and L3 interfaces

Put each port in its own VLAN, untagged, and let untagged frames in (SONiC discards them on ports outside a VLAN; see Building an L2 switch with VLANs and SVIs). Then create an L3 interface in each VLAN with the router MAC:

Hardware-validated

drivshell> vlan create 2001 PortBitMap=xe3 UntagBitMap=xe3
drivshell> vlan create 2002 PortBitMap=ce27 UntagBitMap=ce27
drivshell> pvlan set xe3 2001
drivshell> pvlan set ce27 2002
drivshell> port xe3,ce27 DISCard=None
drivshell> l3 intf add VLAN=2001 MAC=e0:39:d7:88:3b:00
drivshell> l3 intf add VLAN=2002 MAC=e0:39:d7:88:3b:00
drivshell> l3 intf show
Unit  Intf  VRF Group VLAN    Source Mac     MTU TTL Tunnel InnerVlan  NATRealm
0     8196  -3    0     2001 e0:39:d7:88:3b:00  16383 0    0     0     0
0     8197  -3    0     2002 e0:39:d7:88:3b:00  16383 0    0     0     0

The new interfaces are 8196 (host side) and 8197 (core side).

3. Pushing a label

An egress object with MplsLabel pushes that label on every packet sent through it. Create one for the host and one, with label 100, for the other switch, then a host entry and a route that use them:

4. Popping a label

mpls tunnel switch add adds an incoming-label entry. ACTion=1 is PHP: pop the label and send the packet to EgrObject as IPv4. On a SONiC switch the SDK runs in L3 ingress mode, and the command then also needs the L3 interface the labelled packets arrive on (IngIntf, the core interface):

Hardware-validated

drivshell> mpls tunnel switch add ACTion=1 IngLabel=200 EgrObject=132770
L3IngressMode is set - Invalid ingress interface(IngIntf)

Failed to execute the diagnostic command. Error: Operation failed.
drivshell> mpls tunnel switch add ACTion=1 IngLabel=200 EgrObject=132770 IngIntf=8197

The action numbers are those of bcm_mpls_switch_action_t: 0 swap, 1 PHP, 2 pop (then look up the payload), 3 pop and forward directly. The shell has no command to list incoming-label entries; this Cint program does:

mpls_ilm.c
/*
 * mpls_ilm.c - list incoming-label (ILM) entries with
 * bcm_mpls_tunnel_switch_traverse().  Prints the first 50.  Read-only.
 * Run:  cint /root/mpls_ilm.c
 */
cint_reset();

int ilm_count = 0;
int ilm_limit = 50;

int ilm_cb(int unit, bcm_mpls_tunnel_switch_t *info, void *user_data)
{
    int action = info->action;  /* printf does not take enum values */

    ilm_count++;
    if (ilm_count > ilm_limit) {
        return BCM_E_NONE;
    }
    printf("label %d: action %d egress_if %d ingress_if %d port 0x%x flags 0x%x\n",
           info->label, action, info->egress_if, info->ingress_if,
           info->port, info->flags);
    return BCM_E_NONE;
}

int ilm_main()
{
    int unit = 0;
    int rv;

    ilm_count = 0;
    rv = bcm_mpls_tunnel_switch_traverse(unit, ilm_cb, NULL);
    printf("rv %d (%s), %d entries\n", rv, bcm_errmsg(rv), ilm_count);
    return 0;
}

ilm_main();
printf("DONE mpls_ilm\n");

Hardware-validated

rv 0 (Ok), 1 entries
DONE mpls_ilm

6. Checking the path

The hosts can now reach each other, and each packet is routed twice (TTL 62 at the far host):

switch# ping vrf howto-a 203.0.113.11 repeat 5 timeout 1
PING 203.0.113.11 (203.0.113.11) 72(100) bytes of data.
80 bytes from 203.0.113.11: icmp_seq=1 ttl=62 time=0.237 ms
...
5 packets transmitted, 5 received, 0% packet loss, time 0ms

traceroute shows * * * for both switches: packets whose TTL runs out are sent to the CPU, and nothing there answers them.

Troubleshooting

Labelled packets that the far switch does not pop are dropped on its core port and counted in RDBGC0. This happens when the label has no incoming-label entry:

Hardware-validated

drivshell> mpls tunnel switch del IngLabel=100
drivshell> show counters changed ce29
RUC_64.ce29              :                    35                  +5
RDBGC0_64.ce29                   :                    37                  +5
CLMIB_R127.ce29          :                    35                  +5
CLMIB_RPKT.ce29          :                 5,892                  +5
CLMIB_RUCA.ce29          :                    35                  +5
CLMIB_RPRM.ce29          :                    35                  +5
CLMIB_RPOK.ce29          :                 5,892                  +5
CLMIB_RBYT.ce29          :             1,858,539                +610
CLMIB_RPROG3.ce29        :                    35                  +5

It also happens when the destination MAC is not a station with MPLS termination allowed: the chip then switches the frame in the core VLAN like any other frame, finds no other port to send it to, and drops it. RDBGC0 counts several drop reasons together. To see which, list what each debug counter counts with this program; the numbers are those of bcm_custom_stat_trigger_t:

rx_debug_counters.c
/*
 * rx_debug_counters.c - list the drop and event reasons (triggers) that
 * each receive debug counter RDBGC0-RDBGC8 counts, as numbers of the
 * bcm_custom_stat_trigger_t enum (bcm_stat_custom_check).  Read-only.
 * Change rd_port to check another port.
 * Run:  cint /root/rx_debug_counters.c
 */
cint_reset();

int rd_port = 115;

int rd_main()
{
    int unit = 0;
    bcm_stat_val_t ctr[] = {snmpBcmCustomReceive0, snmpBcmCustomReceive1, snmpBcmCustomReceive2,
                            snmpBcmCustomReceive3, snmpBcmCustomReceive4, snmpBcmCustomReceive5,
                            snmpBcmCustomReceive6, snmpBcmCustomReceive7, snmpBcmCustomReceive8};
    int c, t, r, rv;

    for (c = 0; c < 9; c++) {
        printf("RDBGC%d:", c);
        for (t = 0; t < 130; t++) {
            r = 0;
            rv = bcm_stat_custom_check(unit, rd_port, ctr[c], t, &r);
            if (rv == BCM_E_NONE && r) {
                printf(" %d", t);
            }
        }
        printf("\n");
    }
    return 0;
}

rd_main();
printf("DONE rx_debug_counters\n");

RDBGC1: 12

On SONiC RDBGC0 counts 0 (IPv4 discards), 4 (IPv6 discards), 10 (port not forwarding), 11 (policy discard), 15 (no destination port), and 115–118 (VLAN and TPID mismatches). Labelled frames sent to a MAC without MPLS termination counted as trigger 15 on this setup.

Removing it again

Undo it in reverse order on each switch, then put the ports back to SONiC’s settings for ports outside a VLAN (PVID 1, untagged frames discarded):

Hardware-validated

drivshell> mpls tunnel switch del IngLabel=200
drivshell> l3 defip destroy VRF=0 IP=203.0.113.0 MaSk=255.255.255.0
drivshell> l3 l3table destroy VRF=0 IP=192.0.2.11
drivshell> l3 egress delete 132770
drivshell> l3 egress delete 132771
drivshell> l3 intf destroy INTF=8196
drivshell> l3 intf destroy INTF=8197
drivshell> l2 clear Vlanid=2001
L2: Deleting static and non-static addresses by VLAN
drivshell> l2 clear Vlanid=2002
drivshell> pvlan set xe3,ce27 1
drivshell> vlan destroy 2001
drivshell> vlan destroy 2002
drivshell> port xe3,ce27 DISCard=Untag
