SONiC and SDK troubleshooting

Compare SONiC’s view with the SDK’s view before changing switch state. A missing VLAN, an unexpected counter or an unavailable shell can originate at different layers. The checks below help narrow the problem without changing ASIC configuration.

Version information

Record the SONiC image, platform and ASIC model alongside the Broadcom SAI, OCP SAI API and SDK versions. These version numbers describe different components; an SDK release number alone does not identify the SAI package. Use version for SDK build information and bsv for the SAI and Cancun information available in this shell.

The syncd initialization log may also contain all three version labels. Look for that log in existing logs or a SONiC tech-support bundle. If the line is absent, check whether syncd reached initialization; collecting a bundle does not guarantee that the information is present. See the October 2021 shell-access discussion.

The Chips: list from version all describes the SDK build. Do not use it alone as a compatibility guarantee for a Community SAI package, a switch platform or a particular feature. Check the exact package and platform combination. The 2024–2025 ASIC-support discussion illustrates why an SDK chip list and SAI/platform support need to be distinguished.

VLAN configuration ownership

Use SONiC’s VLAN configuration commands for a SONiC-managed VLAN. Creating a Linux bridge with brctl is not a substitute for programming the switch through SONiC. Compare the configured VLAN membership with vlan show and check tagged versus untagged membership explicitly.

The February 2018 VLAN discussion shows a Linux bridge that is absent from the SDK VLAN listing; the reply directs the user to the SONiC VLAN CLI. For current CLI syntax, use the help supplied by your SONiC image. For an isolated exercise that deliberately configures the SDK directly, see Building an L2 switch with VLANs and SVIs and its cleanup instructions.

Counter comparisons

For surprising interface totals, compare SONiC’s interface counters with show counters for the corresponding SDK port. Resolve the port mapping first using Ports and port bitmaps; Linux and SDK port names need not match. Record both views close together, along with link state and time since boot, before clearing anything.

If both views contain implausible values, do not assume the problem is only SONiC’s display or polling layer. Conversely, a difference between the views needs investigation of counter selection and collection timing before it can identify a cause. See Troubleshooting queues and buffers for counter units and drop attribution.

A June 2019 counter report describes unexpectedly large totals after cold boot in both SONiC and bcmsh on a Tomahawk switch. It is a useful comparison to make, not a documented fix for such counters.
