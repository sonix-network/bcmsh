Troubleshooting queues and buffers

This page covers the packet buffer of a Trident 3 switch from the shell: how the buffer is divided between ports, priority groups and queues, where packets are dropped and which counter counts each drop, how to read the buffer high-water marks, and what can be changed. SONiC’s own commands (show queue counters, show queue watermark, mmuconfig) are the normal way to look at queues; the shell adds the raw counters behind them, the hardware limits, and the drops that SONiC does not show.

Everything on this page is read-only unless a section says otherwise. The examples use xe3, a 10G port that carries traffic, and ce30, a 100G port that is down, for the changes.

The buffer in brief

The MMU stores every packet between the ingress and the egress pipeline, in 256-byte cells. The shell, the SDK registers and the BST counters all count in cells; SONiC shows bytes.

A packet passes two admission checks:

Ingress admission (THDI)

The packet’s internal priority (0–15) selects one of the ingress port’s eight priority groups, and the PG selects an ingress service pool. A PG has a minimum (cells reserved for it), a shared limit (how much of the service pool it may take beyond its minimum, static or dynamic), and a headroom (cells that absorb the packets still arriving after a PFC pause is sent). A packet that does not fit is dropped and counted on the ingress port.

Egress admission (THDU for unicast, THDM for multicast)

Every egress queue has its own minimum and shared limit against an egress service pool. The shared limit is usually dynamic: the queue may use alpha times the free cells of the pool, so a single congested queue can take a large share of an idle buffer but less of a busy one. A packet that does not fit is dropped and counted on the egress queue. WRED drops packets earlier, at random, as a queue grows.

Before either check, ports on oversubscribed port macros pass the OBM, a small per-port-macro buffer in front of the ingress pipeline. When it overflows, packets are dropped before they reach the MMU, and no MMU counter sees them.

Each front-panel port has ten unicast and ten multicast queues; SONiC calls them UC0–UC9 and MC10–MC19. The CPU port has 48 multicast queues, the CPU queues used by CoPP. show pmap lists, for each port, its pipe, its MMU port and the first queue number (ucast_Qbase, mcast_Qbase):

       pipe   logical  physical    idb mmu   ucast_Qbase/Numq  mcast_Qbase/Numq  half-pipe
 xe3      0    12        12        11  11       110/10               110/10          0
ce30      1   127       125        60 188       600/10               600/10          0

Those numbers are the indices into the MMU tables. The tables exist once per pipe, with _PIPE0 or _PIPE1 in their name (_XPE0_PIPE0 for counters). For a port:

  • its unicast queue q is entry ucast_Qbase + q of the queue tables of its pipe (xe3 queue 0 is entry 110 of a _PIPE0 table, ce30 queue 3 is entry 603 of a _PIPE1 table);

  • its priority group p is entry m × 8 + p of the PG tables, where m is the mmu number within the pipe: the mmu column for pipe 0, minus 128 for pipe 1 (xe3 PG 7 is entry 95, ce30 PG 7 is entry 487).

See Memories and registers for table names and pipe copies.

Priority groups and service pools

Two registers per ingress port map priorities to PGs (THDI_PORT_PRI_GRP0 for priorities 0–7, THDI_PORT_PRI_GRP1 for 8–15), and THDI_PORT_PG_SPID maps PGs to service pools. Read them with getreg:

The queue as the SDK sees it

Reading tables shows one limit at a time. The queue_info.c CINT program below asks the SDK for everything about the unicast queues of one port: scheduling mode and weight, minimum and alpha, shaper, WRED and the current BST high-water mark. It calls only *_get functions. See Cint recipes for how to copy a program into the syncd container and run it.

queue_info.c
/*
 * queue_info.c - show the queues of one port: scheduler mode and weight,
 * egress admission (min, shared, dynamic, alpha), shaping, WRED, and the
 * BST high-water mark of each unicast queue.  Only calls *_get functions.
 * Set qi_port to the logical port number (from "ps").
 * Run:  cint /root/queue_info.c
 */
cint_reset();

int qi_port = 127;          /* ce30 */
bcm_gport_t qi_uc[16];
bcm_gport_t qi_mc[16];
int qi_nuc = 0;
int qi_nmc = 0;

int qi_cb(int unit, bcm_gport_t port, int numq, uint32 flags,
          bcm_gport_t gport, void *user_data)
{
    bcm_gport_t *want = user_data;
    if (port != *want) {
        return BCM_E_NONE;
    }
    if ((flags & BCM_COSQ_GPORT_UCAST_QUEUE_GROUP) && qi_nuc < 16) {
        qi_uc[qi_nuc] = gport;
        qi_nuc++;
    }
    if ((flags & BCM_COSQ_GPORT_MCAST_QUEUE_GROUP) && qi_nmc < 16) {
        qi_mc[qi_nmc] = gport;
        qi_nmc++;
    }
    return BCM_E_NONE;
}

int qi_main()
{
    int unit = 0;
    int rv, i, arg, mode, weight, dyn, alpha, qmin, qshared;
    uint32 kmin, kmax, bwflags;
    uint64 wm;
    bcm_gport_t pg;
    bcm_cosq_gport_discard_t wred;

    rv = bcm_switch_control_get(unit, bcmSwitchBstEnable, &arg);
    printf("BST enable %d (rv %d)\n", arg, rv);
    rv = bcm_switch_control_get(unit, bcmSwitchBstTrackingMode, &arg);
    printf("BST tracking mode %d (0 current, 1 peak) (rv %d)\n", arg, rv);

    bcm_port_gport_get(unit, qi_port, &pg);
    qi_nuc = 0;
    qi_nmc = 0;
    rv = bcm_cosq_gport_traverse(unit, qi_cb, &pg);
    printf("port %d gport 0x%x: %d UC, %d MC queues (rv %d)\n",
           qi_port, pg, qi_nuc, qi_nmc, rv);

    for (i = 0; i < qi_nuc; i++) {
        mode = -1; weight = -1; dyn = -1; alpha = -1; qmin = -1; qshared = -1;
        kmin = 0; kmax = 0; bwflags = 0;
        bcm_cosq_gport_sched_get(unit, qi_uc[i], 0, &mode, &weight);
        bcm_cosq_control_get(unit, qi_uc[i], 0,
                             bcmCosqControlEgressUCSharedDynamicEnable, &dyn);
        bcm_cosq_control_get(unit, qi_uc[i], 0,
                             bcmCosqControlDropLimitAlpha, &alpha);
        bcm_cosq_control_get(unit, qi_uc[i], 0,
                             bcmCosqControlEgressUCQueueMinLimitBytes, &qmin);
        bcm_cosq_control_get(unit, qi_uc[i], 0,
                             bcmCosqControlEgressUCQueueSharedLimitBytes, &qshared);
        bcm_cosq_gport_bandwidth_get(unit, qi_uc[i], 0, &kmin, &kmax, &bwflags);
        bcm_cosq_gport_discard_t_init(&wred);
        wred.flags = BCM_COSQ_DISCARD_COLOR_GREEN | BCM_COSQ_DISCARD_BYTES;
        bcm_cosq_gport_discard_get(unit, qi_uc[i], 0, &wred);
        COMPILER_64_ZERO(wm);
        rv = bcm_cosq_bst_stat_get(unit, qi_uc[i], 0, bcmBstStatIdUcast, 0, &wm);
        printf("UC%d 0x%x: sched %d weight %d | min %d B, dynamic %d, alpha %d, shared %d | shape %u-%u kbps | wred 0x%x %d-%d B | bst %u (rv %d)\n",
               i, qi_uc[i], mode, weight, qmin, dyn, alpha, qshared,
               kmin, kmax, wred.flags, wred.min_thresh, wred.max_thresh,
               COMPILER_64_LO(wm), rv);
    }
    for (i = 0; i < 8; i++) {
        COMPILER_64_ZERO(wm);
        rv = bcm_cosq_bst_stat_get(unit, pg, i, bcmBstStatIdPriGroupShared, 0, &wm);
        printf("PG%d shared bst %u (rv %d)", i, COMPILER_64_LO(wm), rv);
        COMPILER_64_ZERO(wm);
        rv = bcm_cosq_bst_stat_get(unit, pg, i, bcmBstStatIdPriGroupHeadroom, 0, &wm);
        printf(", headroom bst %u (rv %d)\n", COMPILER_64_LO(wm), rv);
    }
    return 0;
}

qi_main();
printf("DONE queue_info\n");

How to read it:

sched 3 weight 1

Scheduling mode BCM_COSQ_WEIGHTED_ROUND_ROBIN (1 is strict priority, 5 deficit round robin), weight 1.

alpha 7

bcmCosqControlDropLimitAlpha_2 in this build’s numbering: alpha 2. Look enum values up in Cint API on this build; they differ between SDK releases.

shared 2048

In dynamic mode this is the alpha code (8) multiplied by the cell size, not a limit. Ignore it when dynamic is 1.

shape 0-0

No minimum and no maximum rate.

wred 0x2100

BCM_COSQ_DISCARD_COLOR_GREEN | BCM_COSQ_DISCARD_BYTES without BCM_COSQ_DISCARD_ENABLE: WRED is off.

0x241fc000

The queue’s GPORT, needed by every bcm_cosq_gport_* call and by cos discard_show Gport=.

PG<n>

The loop index is passed as a priority; the SDK maps it to the PG. Here all eight lines therefore show PG 7.

The global cos show and cos port show do not show these queue settings; they show the SDK’s port-level scheduler view (see Changing queues from the shell).

SONiC QoS and the hardware

SONiC configures queues and buffers through config_db tables, usually rendered from the HWSKU’s qos.json.j2 and buffers.json.j2 by config qos reload. orchagent turns them into SAI objects and the SAI programs the tables above. The mapping:

In SONiC a dynamic_th of n means alpha 2n, the same scale as the alpha code above (dynamic_th 1 is code 8).

show queue counters, show queue watermark, show priority-group watermark, show buffer_pool watermark and show pfc counters read these values through the SAI; mmuconfig -l lists the pools and profiles SONiC has configured. On a switch without buffer configuration in config_db it prints only:

admin@sonic:~$ mmuconfig -l
No buffer pool information available
No buffer profile information available

and the queues run with the SAI’s defaults shown above: all priorities in PG 7, lossy, every queue weighted round robin with weight 1, alpha 2, no shaper and no WRED.

Watching counters

show counters with no options prints only counters that changed since the last show counters and are not zero. The second number on each line is that change. The diag shell has one memory of the last values for everybody, so if another session or a script also runs show counters, the change column is relative to their last call. For a clean measurement, take show counters all <port> twice and compare the first numbers.

Two things do not work as one might expect:

  • A per-queue counter cannot be selected by name:

clear counters (clear) sets the hardware counters to zero, and SONiC’s counters (which read the same registers) jump with them. Prefer differences. If you must clear, clear only the port you are testing (clear c ce30).

Watermarks

The hardware tracks the highest buffer use it has seen with BST (Buffer Statistics Tracking). BST is on for ingress (THDI), egress (THDO) and the free-cell pool (CFAP):

Hardware-validated

drivshell> g MMU_GCFG_BST_TRACKING_ENABLE
MMU_GCFG_BST_TRACKING_ENABLE.mmu_glb0[5][0xa000e00]=7: <BST_TRACK_EN_THDO=1,
   BST_TRACK_EN_THDI=1,BST_TRACK_EN_CFAP=1>

SONiC and the watermarks

SONiC reads the watermarks through the SAI every 60 seconds and clears them as it reads (flex counter groups QUEUE_WATERMARK_STAT, PG_WATERMARK_STAT and BUFFER_POOL_WATERMARK_STAT, stats mode READ_AND_CLEAR). It keeps the maxima itself:

  • show queue watermark, show priority-group watermark, show buffer_pool watermark: the highest value since the last telemetry period (config watermark telemetry interval, 120 s by default) or sonic-clear … watermark;

  • show … persistent-watermark: the highest value since the last sonic-clear … persistent-watermark.

counterpoll show lists the polling intervals, and counterpoll watermark interval <ms> changes them.

For the shell this means that a watermark can drop back to zero under you up to once a minute. Read the hardware table, not the SDK, if you want the value since SONiC’s last read, and use SONiC’s persistent-watermark for long-term maxima.

The SDK’s BST API (bcm_cosq_bst_stat_get) returns the SDK’s own copy, which is updated only when someone calls bcm_cosq_bst_stat_sync and which SONiC’s read-and-clear empties. Called on its own it usually returns 0, as in the queue_info.c output above. Sync first:

bst_sync.c
/*
 * bst_sync.c - pull the hardware BST high-water marks into the SDK's copy,
 * then read the unicast-queue and priority-group marks of one port.
 * Set bs_port to the logical port number (from "ps").
 * Run:  cint /root/bst_sync.c
 */
cint_reset();

int bs_port = 12;           /* xe3 */

int bs_cb(int unit, bcm_gport_t port, int numq, uint32 flags,
          bcm_gport_t gport, void *user_data)
{
    bcm_gport_t *want = user_data;
    uint64 wm;
    int rv;
    if (port != *want || !(flags & BCM_COSQ_GPORT_UCAST_QUEUE_GROUP)) {
        return BCM_E_NONE;
    }
    COMPILER_64_ZERO(wm);
    rv = bcm_cosq_bst_stat_get(unit, gport, 0, bcmBstStatIdUcast, 0, &wm);
    if (COMPILER_64_LO(wm) != 0 || rv != 0) {
        printf("UC queue 0x%x: %u cells (rv %d)\n", gport, COMPILER_64_LO(wm), rv);
    }
    return BCM_E_NONE;
}

int bs_main()
{
    int unit = 0;
    int rv, i;
    uint64 wm;
    bcm_gport_t pg;

    rv = bcm_cosq_bst_stat_sync(unit, bcmBstStatIdUcast);
    printf("sync Ucast: rv %d\n", rv);
    rv = bcm_cosq_bst_stat_sync(unit, bcmBstStatIdPriGroupShared);
    printf("sync PriGroupShared: rv %d\n", rv);

    bcm_port_gport_get(unit, bs_port, &pg);
    bcm_cosq_gport_traverse(unit, bs_cb, &pg);
    for (i = 0; i < 8; i++) {
        COMPILER_64_ZERO(wm);
        rv = bcm_cosq_bst_stat_get(unit, pg, i, bcmBstStatIdPriGroupShared, 0, &wm);
        printf("PG%d shared: %u cells (rv %d)\n", i, COMPILER_64_LO(wm), rv);
    }
    return 0;
}

bs_main();
printf("DONE bst_sync\n");

Changing queues from the shell

The persistent way to change queues and buffers is SONiC’s configuration: edit SCHEDULER, WRED_PROFILE, QUEUE, BUFFER_PROFILE, BUFFER_PG, BUFFER_QUEUE and the maps in config_db (or the HWSKU templates and config qos reload), or use mmuconfig -p <profile> -a <dynamic_th> to change a buffer profile’s alpha. orchagent then reprograms the queues. The start-up MMU layout comes from config.bcm; see Buffers and queues.

The shell can change the same hardware, which is useful to try a value before writing it into SONiC’s configuration.

Warning

A queue or buffer change made in the shell is invisible to SONiC. SONiC writes its own value back whenever it reprograms that object: when the matching config_db entry changes, on config qos reload or config reload, and when swss or syncd restarts or the switch reboots. Until then the shell value stays. On a port that SONiC has no QoS configuration for, that means until syncd restarts. Write down the old value before every change and put it back when you are done. To return to SONiC’s configuration, run sudo config qos reload if the switch uses SONiC QoS tables, or sudo config reload (this restarts swss and syncd and interrupts traffic). Do not change service pool sizes or global registers on a switch that forwards traffic.

Per-queue settings through the API

The SDK functions that SONiC’s SAI itself uses are the safe way to change a queue, because they keep the SDK’s software state consistent with the hardware. queue_tune.c saves the settings of one unicast queue, changes four of them, shows the result and puts the old values back:

  • bcm_cosq_gport_sched_set: scheduling mode and weight;

  • bcm_cosq_control_set with bcmCosqControlDropLimitAlpha: the dynamic shared limit;

  • bcm_cosq_gport_bandwidth_set: minimum and maximum rate in kbit/s;

  • bcm_cosq_gport_discard_set: WRED per colour (add BCM_COSQ_DISCARD_MARK_CONGESTION to ECN-mark instead of drop).

queue_tune.c
/*
 * queue_tune.c - change one unicast queue of one port: WRR weight, shared
 * limit alpha, maximum rate and green WRED thresholds; print the result;
 * then, with qt_restore = 1, put the old values back.
 * Changes the ASIC behind SONiC's back.  Set qt_port (logical port number
 * from "ps") and qt_queue.
 * Run:  cint /root/queue_tune.c
 */
cint_reset();

int qt_port = 127;          /* ce30 */
int qt_queue = 3;
int qt_restore = 1;
bcm_gport_t qt_gp = 0;

int qt_cb(int unit, bcm_gport_t port, int numq, uint32 flags,
          bcm_gport_t gport, void *user_data)
{
    bcm_gport_t *want = user_data;
    if (port == *want && (flags & BCM_COSQ_GPORT_UCAST_QUEUE_GROUP)) {
        if (qt_queue == 0) {
            qt_gp = gport;
        }
        qt_queue--;
    }
    return BCM_E_NONE;
}

int qt_show(int unit, char *when)
{
    int mode = -1, weight = -1, alpha = -1;
    uint32 kmin = 0, kmax = 0, fl = 0;
    bcm_cosq_gport_discard_t w;

    bcm_cosq_gport_sched_get(unit, qt_gp, 0, &mode, &weight);
    bcm_cosq_control_get(unit, qt_gp, 0, bcmCosqControlDropLimitAlpha, &alpha);
    bcm_cosq_gport_bandwidth_get(unit, qt_gp, 0, &kmin, &kmax, &fl);
    bcm_cosq_gport_discard_t_init(&w);
    w.flags = BCM_COSQ_DISCARD_COLOR_GREEN | BCM_COSQ_DISCARD_BYTES;
    bcm_cosq_gport_discard_get(unit, qt_gp, 0, &w);
    printf("%-8s sched %d weight %d | alpha %d | max %u kbps | wred flags 0x%x min %d max %d prob %d\n",
           when, mode, weight, alpha, kmax, w.flags, w.min_thresh,
           w.max_thresh, w.drop_probability);
    return 0;
}

int qt_main()
{
    int unit = 0;
    int rv;
    int mode, weight, alpha;
    uint32 kmin, kmax, fl;
    bcm_gport_t pg;
    bcm_cosq_gport_discard_t old_w;
    bcm_cosq_gport_discard_t new_w;

    bcm_port_gport_get(unit, qt_port, &pg);
    bcm_cosq_gport_traverse(unit, qt_cb, &pg);
    printf("queue gport 0x%x\n", qt_gp);
    if (qt_gp == 0) {
        return BCM_E_NOT_FOUND;
    }

    /* Save the current values. */
    bcm_cosq_gport_sched_get(unit, qt_gp, 0, &mode, &weight);
    bcm_cosq_control_get(unit, qt_gp, 0, bcmCosqControlDropLimitAlpha, &alpha);
    bcm_cosq_gport_bandwidth_get(unit, qt_gp, 0, &kmin, &kmax, &fl);
    bcm_cosq_gport_discard_t_init(&old_w);
    old_w.flags = BCM_COSQ_DISCARD_COLOR_GREEN | BCM_COSQ_DISCARD_BYTES;
    bcm_cosq_gport_discard_get(unit, qt_gp, 0, &old_w);
    qt_show(unit, "before");

    /* Change them. */
    rv = bcm_cosq_gport_sched_set(unit, qt_gp, 0, BCM_COSQ_WEIGHTED_ROUND_ROBIN, 10);
    printf("sched_set WRR 10: %s\n", bcm_errmsg(rv));
    rv = bcm_cosq_control_set(unit, qt_gp, 0, bcmCosqControlDropLimitAlpha,
                              bcmCosqControlDropLimitAlpha_1);
    printf("alpha 1: %s\n", bcm_errmsg(rv));
    rv = bcm_cosq_gport_bandwidth_set(unit, qt_gp, 0, 0, 10000000, 0);
    printf("max 10 Gb/s: %s\n", bcm_errmsg(rv));
    bcm_cosq_gport_discard_t_init(&new_w);
    new_w.flags = BCM_COSQ_DISCARD_ENABLE | BCM_COSQ_DISCARD_COLOR_GREEN |
                  BCM_COSQ_DISCARD_BYTES;
    new_w.min_thresh = 100000;
    new_w.max_thresh = 400000;
    new_w.drop_probability = 10;
    rv = bcm_cosq_gport_discard_set(unit, qt_gp, 0, &new_w);
    printf("wred green 100000-400000 B, 10 percent: %s\n", bcm_errmsg(rv));
    qt_show(unit, "after");

    if (qt_restore) {
        bcm_cosq_gport_sched_set(unit, qt_gp, 0, mode, weight);
        bcm_cosq_control_set(unit, qt_gp, 0, bcmCosqControlDropLimitAlpha, alpha);
        bcm_cosq_gport_bandwidth_set(unit, qt_gp, 0, kmin, kmax, fl);
        bcm_cosq_gport_discard_set(unit, qt_gp, 0, &old_w);
        qt_show(unit, "restored");
    }
    return 0;
}

qt_main();
printf("DONE queue_tune\n");

The WRED thresholds are rounded up to whole cells (100000 → 100096 bytes). While WRED was on, cos discard_show Gport=0x241fc003 Queue=0 showed Ena 1 for all three colours, so enabling WRED for one colour enables the queue’s WRED; the yellow and red thresholds stay at their maximum.

The same API covers the other limits: bcm_cosq_control_set with bcmCosqControlEgressUCQueueMinLimitBytes, bcmCosqControlEgressUCQueueSharedLimitBytes and bcmCosqControlEgressUCSharedDynamicEnable on a queue GPORT, and with bcmCosqControlIngressPortPGMinLimitBytes, bcmCosqControlIngressPortPGSharedLimitBytes and bcmCosqControlIngressPortPGHeadroomLimitBytes on a port GPORT and a priority. A queue or PG minimum is taken out of the shared pool, so the SDK may recompute shared limits of other ports when it changes. Leave minimums to SONiC on a switch that carries traffic.

PFC

show pfc counters (SONiC) shows received and sent pause frames per priority. In the shell they are the MAC counters CLMIB_RPFC<n> and CLMIB_TPFC<n>, and CLMIB_RPFCOFF<n>/CLMIB_TPFCOFF<n> for XON. A lossless priority needs, in order: its TC mapped to a PG with headroom (PG_HDRM_LIMIT non-zero in THDI_PORT_PG_CONFIG), PFC enabled on the port (pfc_enable in PORT_QOS_MAP) and, on the egress side, a queue that is not dropped by WRED. If a lossless PG still drops (DROP_PKT_ING rising), check PG_BST_STAT_HDRM against PG_HDRM_LIMIT: a headroom that fills up is too small for the cable length and speed.

Troubleshooting checklist

  1. show queue counters <port> and show interfaces counters: is anything dropped, and on which side?

  2. show c all <port> on the egress port: PERQ_DROP_PKT_UC(q) or PERQ_WRED_DROP_PKT_UC(q) rising points at one queue; check its limit and WRED with queue_info.c and cos discard_show.

  3. On the ingress ports: DROP_PKT_ING rising means ingress admission; look at the PG limits and THDI_PORT_PG_BST. OBM_* rising means the port macro is oversubscribed.

  4. On cpu0: PERQ_DROP_PKT(q) is a CPU queue overflowing; see Protecting the CPU with CoPP.

  5. show queue watermark / show priority-group watermark: how close did the queue or PG get to its limit? Compare with the limit in cells.

  6. Nothing counted anywhere: the drop is in the pipeline, not the buffer; see customstat and show dropcounters.
