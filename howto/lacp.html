Port channels and LACP

A SONiC port channel is a trunk in the switch chip: a group of ports that the chip treats as one, spreading traffic over the members by a hash of each packet’s headers. LACP itself does not run in the chip. teamd on the switch CPU sends and receives the LACP packets (LACPDUs) and decides which members may carry traffic; the SAI then programs that decision into the trunk.

This page shows how to find a port channel’s trunk, how to see the LACPDUs, and how to tell from the diag shell whether a member is really carrying traffic. How LACPDUs reach the CPU is covered in Protecting the CPU with CoPP.

Finding the trunk

trunk show lists every trunk with its member ports. Each SONiC port channel is one trunk; trunk 0 belongs to the SAI and has no ports.

Hardware-validated

drivshell> trunk show
Device supports 2112 trunk groups:
  2048 front panel trunks (0..2047), 256 ports/trunk
  64 fabric trunks (2048..2111), 64 ports/trunk
trunk 0: (front panel, 0 ports)
trunk 1: (front panel, 3 ports)=xe0,xe1,xe2 dlf=any mc=any ipmc=any psc=portflow (0x9)

PortChannel2 with members Ethernet8–Ethernet10 is trunk 1 with xe0–xe2. psc=portflow is the port-selection criterion: the hash over the packet’s addresses and ports that picks a member for each flow.

LACPDUs

With the fast LACP timer each side sends one LACPDU per second on every member. An LACPDU is 128 bytes on the wire, so it counts in the 128–255 byte size bucket and as multicast:

Hardware-validated

drivshell> show c xe2
CLMIB_R255.xe2                   :               259,050             +32,480
CLMIB_RPKT.xe2                   :               259,120             +32,490               1/s
CLMIB_RMCA.xe2                   :               259,055             +32,480
CLMIB_T255.xe2                   :               250,276             +31,419
CLMIB_TPKT.xe2                   :               258,715             +32,488               1/s
CLMIB_TMCA.xe2                   :               258,666             +32,474

The rate column shows one packet per second in each direction on an otherwise idle member. If the receive side stays at zero the partner is not sending LACPDUs (or the link is not up); if the transmit side stays at zero, teamd is not sending. Received LACPDUs are trapped to the CPU by the lacp CoPP entry (see Protecting the CPU with CoPP).

A member that LACP has taken out

When the partner stops sending LACPDUs on a member, teamd deselects it after three missed LACPDUs. SONiC shows it as (D):

$ show interfaces portchannel
...
    2  PortChannel2  LACP(A)(Up)  Ethernet8(S) Ethernet9(S) Ethernet10(D)

The link is still up, and the trunk still lists the port:

Hardware-validated

drivshell> trunk show
Device supports 2112 trunk groups:
  2048 front panel trunks (0..2047), 256 ports/trunk
  64 fabric trunks (2048..2111), 64 ports/trunk
trunk 0: (front panel, 0 ports)
trunk 1: (front panel, 3 ports)=xe0,xe1,xe2 dlf=any mc=any ipmc=any psc=portflow (0x9)
drivshell> ps xe2
                 ena/        speed/ link auto    STP                  lrn  inter   max   cut   loop
           port  link  Lns   duplex scan neg?   state   pause  discrd ops   face frame  thru?  back   encap
       xe2( 11)  up     1   10G  FD   SW  No   Forward           All    F    XFI  9122    No          IEEE

The SAI does not remove a deselected member from the trunk. It disables it instead: the port discards everything it receives (All in the discrd column of ps; Disc(all) in port xe2), and the trunk member is marked as disabled for ingress and egress, so the hash no longer picks it. trunk show does not show these member flags; the Cint program below does:

trunk_members.c
/*
 * trunk_members.c - print the member ports of trunk 1 with their
 * per-member flags (bcm_trunk_get).  Read-only.
 * Change tm_tid to look at another trunk.
 * Run:  cint /root/trunk_members.c
 */
cint_reset();

int tm_tid = 1;

int tm_main()
{
    int unit = 0;
    bcm_trunk_info_t info;
    bcm_trunk_member_t m[16];
    int count, i, rv;
    bcm_port_t port;

    rv = bcm_trunk_get(unit, tm_tid, &info, 16, m, &count);
    printf("bcm_trunk_get: %s, %d members, psc %d\n", bcm_errmsg(rv), count, info.psc);
    for (i = 0; i < count; i++) {
        bcm_port_local_get(unit, m[i].gport, &port);
        printf("  port %3d flags 0x%03x%s%s\n", port, m[i].flags,
               (m[i].flags & BCM_TRUNK_MEMBER_EGRESS_DISABLE) ? " egress-disabled" : "",
               (m[i].flags & BCM_TRUNK_MEMBER_INGRESS_DISABLE) ? " ingress-disabled" : "");
    }
    return 0;
}

tm_main();
printf("DONE trunk_members\n");

Hardware-validated

drivshell> cint /root/trunk_members.c
bcm_trunk_get: Ok, 3 members, psc 9
  port   9 flags 0x000
  port  10 flags 0x000
  port  11 flags 0x003 egress-disabled ingress-disabled
DONE trunk_members

flags 0x003 is BCM_TRUNK_MEMBER_INGRESS_DISABLE (1) plus BCM_TRUNK_MEMBER_EGRESS_DISABLE (2). A member that carries traffic has flags 0x000 and Untag (the normal setting for a port outside any VLAN) in the discrd column.

So to see which members of a port channel carry traffic, look at the discrd column of ps or at the member flags, not at trunk show.

A member whose link is down

A member whose link goes down is handled the same way: it stays in the trunk, disabled, with discrd All:

Hardware-validated

drivshell> cint /root/trunk_members.c
bcm_trunk_get: Ok, 3 members, psc 9
  port   9 flags 0x000
  port  10 flags 0x000
  port  11 flags 0x003 egress-disabled ingress-disabled
DONE trunk_members
drivshell> ps xe2
                 ena/        speed/ link auto    STP                  lrn  inter   max   cut   loop
           port  link  Lns   duplex scan neg?   state   pause  discrd ops   face frame  thru?  back   encap
       xe2( 11)  down   1   10G  FD   SW  No   Forward           All    F    XFI  9122    No          IEEE

When the link comes back and LACP selects the port again, the flags return to 0x000:

Hardware-validated

drivshell> cint /root/trunk_members.c
bcm_trunk_get: Ok, 3 members, psc 9
  port   9 flags 0x000
  port  10 flags 0x000
  port  11 flags 0x000
DONE trunk_members

Changing trunks

trunk add and trunk remove change the member list behind SONiC’s back: teamd keeps its own view of the members and the SAI does not notice the change, so the two disagree until the port channel is reconfigured. To take a member out for testing, shut down the port or remove it from the port channel in SONiC instead.
