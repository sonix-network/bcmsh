Ports, lanes and SerDes

Logical-to-physical port mapping, breakout, lane swaps and polarity, transmit equalisation, auto-negotiation and link scanning. See Port mapping and SerDes for the formats and worked examples.

Set in several SONiC Trident 3 HWSKU files: dport_map_enable, dport_map_port, higig2_hdr_mode, module_64ports, oversubscribe_mixed_sister_25_50_enable, oversubscribe_mode, pbmp_gport_stack, pbmp_oversubscribe, pbmp_xport_xe, phy_an_c37, phy_an_c73, phy_chain_rx_lane_map_physical, phy_chain_rx_polarity_flip_physical, phy_chain_tx_lane_map_physical, phy_chain_tx_polarity_flip_physical, phy_port_primary_and_offset, port_flex_enable, port_gmii_mode, port_init_autoneg, port_phy_addr, portmap, serdes_core_rx_polarity_flip_physical, serdes_core_tx_polarity_flip_physical, serdes_driver_current, serdes_if_type, serdes_preemphasis.

bcm_linkscan_errdelay
Type:
number
Default:
10000000

The amount of time in microseconds for which the bcm_linkscan module will suspend a port from further update processing after “bcm_linkscan_maxerr” errors are detected. After this delay, the error state for the port is cleared and normal linkscan processing resumes on the port.

Forms:

bcm_linkscan_errdelay_<port>, bcm_linkscan_errdelay_<type>, bcm_linkscan_errdelay

Type:

Enable translation of system port numbers to physical port numbers in hardware (if supported by the switch device). This feature may be used to complement the BCM API translation feature, but can also be used to limit the use of module IDs on devices with 32 or fewer ports in case some physical port numbers reside beyond 31.

dport_map_direct
Type:
number

Traditionally, specifying a raw number instead of a port name in the diag shell will be parsed as if port numbers are counted from 1 up to the number of enabled ports. Typically this would mean that for a gigabit switch, port 1 would correspond to ge0, and so forth. Setting this flag causes raw port numbers to be parsed as internal port numbers.

dport_map_indexed
Type:
number

Port names for each port type (fe, ge, etc.) will increment by one starting at zero, e.g. if a switch has four xe ports with dport numbers 24, 25, 26, and 27, they will be named xe0, xe1, xe2, and xe3. In non-indexed mode the ports would be named xe24, xe25, xe26, and xe27.

phy_topology
Type:
number

Describes how the lanes of a logical port pass through an external PHY (gearbox or retimer) when the lane order is not a simple logical-to-logical mapping, for example when a port spans several SerDes cores or one core is muxed onto several line-side ports. The SDK uses it to find the physical lane behind a logical lane, for example to run PRBS on one lane. Two forms:

  • phy_topology_<pport>_<xphy>=<mdio>:<sys_lane>:<line_lane>

  • phy_topology_<pport>_<xphy>_map<n>=<mdio>:<sys_lane>:<line_lane>, when one port needs several lane entries

<pport> is the physical port, <xphy> the position of the external PHY in the chain (see phy_chain_length), <mdio> its MDIO address, <sys_lane> and <line_lane> the physical lane numbers on its system and line side, and <n> the index of the entry for that port and PHY.

First form: three internal cores connected to one external PHY, with the lane swap crossing the core boundary between cores 1 and 2. Logical lane 4 (core 1, lane 0) is physical lane 8 on the external PHY’s system side:

 ________          ________
|        |________|        |
|        |        |        |
|        |________|        |
| CORE0  |        | EXTPHY |
|        |________|        |
|        |        |        |
|        |________|        |
|________|        |        |
                  |        |
         Sys side |        |
 ________         |        |
|        |        |        | Line side
|        |\       |        |__________
|        | \      |        |
| CORE0  |\ \    /|        |__________
|        | \ \  / |        |
|        |\ \ \/ /|        |__________
|        | \ \/\/ |        |
|________|\ \/\/\/|        |__________
           \/\/\/\|        |
 ________  /\/\/\ |        |
|        |/ /\/\ \|        |
|        | / /\ \ |        |
|        |/ /  \ \|        |
| CORE0  | /    \ | EXTPHY |
|        |/      \|        |
|        |        |        |
|        |________|        |
|________|        |________|

Second form (mux mode): one core connected to an external PHY that splits its line side into two ports of four lanes, each using two system-side lanes:

                   ________
                  |        |
 ________         |        |__________
|        |________|        |__________\
|        |        |        |__________ - PORT1
|        |________|        |__________/
|        |        |        |
|  CORE  |        | EXTPHY |
|        |________|        |__________
|        |        |        |__________\
|        |________|        |__________ - PORT2
|________|        |        |__________/
                  |        |
                  |________|
         Sys side           Line side

The matching entries, with the external PHY at MDIO address 0x10 and the first physical port 8:

# Port 1
phy_topology_8_1_map1=0x10:0:0
phy_topology_8_1_map2=0x10:0:1
phy_topology_9_1_map1=0x10:1:2
phy_topology_9_1_map2=0x10:1:3
# Port 2
phy_topology_10_1_map1=0x10:1:4
phy_topology_10_1_map2=0x10:1:5
phy_topology_11_1_map1=0x10:1:6
phy_topology_11_1_map2=0x10:1:7

Not needed on switches without external PHYs, such as the Trident 3 switches SONiC runs on.

Forms:

phy_topology_<pport>_<xphy>, phy_topology_<pport>_<xphy>_map<n>
