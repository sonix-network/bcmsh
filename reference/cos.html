COS

Manage classes of service

COS

Class-of-service settings: the number of queues, the priority-to-queue map, the scheduling mode and weights, WRED (discard) and per-queue bandwidth, either for the whole switch or per port (cos port …).

Type the sub-commands in full; case does not matter. cos delay and cos port delay also work as names for bounded, although the help does not show them. Parameters (Pri=, Queue=, W0= …, PortBitMap=, KbpsMIn= …) can be shortened to their upper-case letters.

Scheduling sub-commands act immediately even without parameters: cos strict and cos simple switch the scheduling mode at once, and cos weight with no weights re-applies the current weights in weighted mode. Use cos show and cos port show to look.

show, port show, discard_show and bandwidth_show are read-only. Everything else changes queueing and scheduling that SONiC configures (SCHEDULER, WRED_PROFILE, TC_TO_QUEUE_MAP), and SONiC does not see the change. Some of these settings may not be supported on Trident 3; the shell then prints an SDK error.

Warning

cos clear resets the whole COS configuration to SDK defaults, undoing SONiC’s QoS setup.

See also Troubleshooting queues and buffers for reading and changing the queues that SONiC programs, which these commands do not show.

Global

cos show

Show the global COS configuration: COS configuration:, Config (max queues): <n>, Schedule mode: <mode>, the per-queue weights under Weighting (in packets): (COSQ <q> = <w> packets), and Priority to queue mappings: with PRIO <p> ==> COSQ <q> lines for priorities 0–15. Read-only. A Bounded delay line appears only in bounded-delay mode; the WRED summary is printed by cos discard_show.

On a SONiC switch it shows 8 queues, weighted round-robin with weight 1 on every queue, priority p on queue p and priorities 8–15 on queue 7. These global values need not match SONiC’s QoS configuration, which the SAI programs per port on scheduler nodes.

cos discard_port [PortBitMap=<pbmp>] [Queue=<q>] [Color=<green|yellow|red>] [DropSTart=<n>] [DropSLope=<n>] [AvgTime=<n>] [Gport=<gport>]

Unvalidated

drivshell> cos discard_port pbm=ce0 queue=3 color=green dropstart=80 dropslope=10 avgtime=0
cos discard_show [Gport=<gport>] [Queue=<q>]

Show the WRED configuration: the per-port start/slope/time table, or for a GPORT the per-colour Min/Max/Gain/DropProb lines. Read-only.

The first line is the global state, Discard (WRED): discard disabled, cap-average disabled on a SONiC switch. The table then has one block per port, every ce and xe port: eight rows for the port’s queues, then rows marked U for each of its scheduler queues. On a switch with 36 front-panel ports that is over 8000 lines; give Gport= and Queue= to see one queue.

Per port and GPORT

cos port show [PortBitMap=<pbmp>]

Show the per-port COS configuration (Port <p> COS configuration:): schedule mode, weights and priority→queue map. It also traverses the port’s COSQ GPORTs. Read-only.

The weights include a ninth line, COSQ 8 = <w> packets (queue for output of S1 scheduler). After the priority map come repeated VLAN COSQ Schedule mode / VLAN COSQ Weighting blocks for the port’s scheduler nodes (VLAN COSQ 0 to 15), about 575 lines for one ce port.
