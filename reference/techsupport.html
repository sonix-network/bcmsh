TeCHSupport

Collects information required to debug a given feature or subfeature

TeCHSupport

Shortest form: tchs.

Collect debug information about a feature and print it to the console: the feature’s diag-shell commands, its registers and memories, and its SDK software-state dumps. techsupport basic collects general setup information. techsupport all runs basic and then every feature this chip supports. This is the SDK’s own collector. It is separate from SONiC’s show techsupport, which runs a fixed list of bcmcmd commands (scripts/generate_dump (show techsupport collector)), and from the SAI’s BCMSAI TechSupport (BCMSAI).

The feature name must be typed in full. On Trident 3 these features are supported: ifp, vfp, efp, mpls, cos, mmu, vxlan, niv, vlan, riot, flex_flow, load-balance, l3uc, l3mc, cmic, visibility, warmboot and cancun. The other features in the built-in help (etrap, int, histogram, alpm, oam, tcb, dgm, pstat, PHY, LEDUP, flowtracker) print command "techSupport <name>" not supported on chip <chip>.

Options after the feature name narrow what is collected. Without any option, everything is collected. Each collected command is framed by >>>…Output of "<command>" start>>>… and <<<…Output of "<command>" end<<<… lines. Registers are read with getreg chg and memories with dump chg, so by default only values that differ from the reset values appear.

  • diag: only the diag-shell commands.

  • reg: only registers. mem: only memories. sw: only the software-state dumps.

  • verbose: dump whole tables. By default only entries that differ from their reset values are dumped.

  • list: print what would be collected, without running anything.

  • generate-script: print the collection as a script of commands, without running it. The built-in help does not mention it.

basic and all take no options.

Safety on a running switch

Form

Effect

basic, all, feature collections, list, generate-script

Read-only, but output can be very large and keeps the shell busy while it runs. On a SONiC Trident 3 switch a feature with diag took 1 to 3 seconds; basic printed about 22,000 lines in 13 seconds, cancun (all of its parts) 12,500 lines in 15 seconds, cos diag 48,000 lines, and all more than 27 MB in over ten minutes. basic also runs show counters, which moves the “changed” baseline of show counters.

visibility

Sends a trace packet into the switch pipeline. With trace option 0x4 (forward) the packet may be forwarded.

TeCHSupport all

Run basic and then every supported feature in turn. Each step is framed by START: Executing "techSupport <name>". and END: … lines, followed by the time it took. Read-only, but it takes a long time.

Warning

On a SONiC Trident 3 switch techsupport all ran for more than ten minutes and printed more than 27 MB. It keeps running inside syncd after the bcmcmd client times out, and until it finishes no other bcmcmd or bcmsh session gets the shell. Run it only when you need it, give bcmcmd a long timeout (-t 3600) and send the output to a file; for most purposes basic or a single feature is enough.

Unvalidated

drivshell> techsupport all
TeCHSupport visibility <data=<hex> | file=<path>> sourceport=<port> [options=<flags>] [raw]

Trace a packet through the switch pipeline as if it arrived on sourceport. Give the packet as hex bytes (data=) or a file (file=). The trace options are listed in the built-in help (0x1 to 0x10). raw dumps the raw trace data. Without raw the packet is sent with the tx command, which may not be available in SONiC. This sends a packet into the pipeline; see the safety table.
