BCMSAI

SAI BCM shell commands

BCMSAI

Added to the shell at runtime rather than built in.

Debug commands of the Broadcom SAI itself, as opposed to the SDK. The SAI adds BCMSAI to the shell when it creates the switch, so it is available once syncd has finished initialising. It replaces any SDK command of the same name.

Keywords are matched case-insensitively and each can be abbreviated: the upper-case letters of a keyword below are the characters an abbreviation must contain. The first keyword that matches wins. Numbers are decimal only, and anything that is not a number reads as 0. Most dumps always show unit 0, whatever unit prefix the command line has.

BCMSAI with no argument prints the built-in help below. An unknown first word prints no help; the drivshell> front-end reports it as “Failed to execute the diagnostic command” (see The drivshell> front-end).

Many dumps print only their headings on a SONiC Trident 3 switch, because the feature behind them is not in use or not available on the chip: L2Ecmp, VlanStack, MPTnl (no VXLAN tunnels), srv6 (SRV6 not enabled), clm (CLM supported: NO) and the flexctr port-* forms (Not supported on non LTSW devices).

In several places the built-in help does not match what the shell accepts; see SyncDB, Hamem, Acl and route.

Safety summary

Sub-command

Effect

VERsion, ObjectState (dump forms), Memtrack, Hamem, Scaletrack, MPTnl, L2Ecmp, VlanStack, SamplePacket, route, flexctr, Acl, LoadBalance, WBInfo, dump_eapp_config, clm show, clm port <id> get delay, srv6 dumps

Display only.

ApiLog, Cint

Print a fixed “not included in SAI build” message.

ObjectState Configure …, clm mode, clm port <id> set …, clm port <id> tx, srv6 global clrctr, TechSupport Config …

Change SAI or SDK state.

TechSupport (dump forms), SyncDB Data Dump

Write files and turn the shell console off and on, or write a debug dump.

DataManager …, SyncDB Table Dump

Tear down and save SAI state before dumping. Not safe on a running switch.

Warning

BCMSAI DataManager … and BCMSAI SyncDB Table Dump run part of the SAI’s shutdown and save path before they dump anything. syncd keeps answering shell commands afterwards, but a later warm reboot or forwarding may be affected. Do not use them on a production switch.

BCMSAI SyncDB Table Dump <table_name>

Dump one syncdb table. Take the name from BCMSAI SyncDB Table List; names longer than 127 characters are truncated. An unknown name prints Table "<name>" not found.

This is not read-only: before dumping, it saves the SAI state and shuts down the HA shared memory, and prints SyncDB save failed. if the save fails. See the warning above.

Unvalidated

drivshell> BCMSAI SyncDB Table Dump <table_name>
BCMSAI SyncDB Data Dump

Write a syncdb debug dump. The built-in help says this “will dump data into /tmp/debug”. The shell itself prints only Got Debug message....

Hardware-validated

drivshell> BCMSAI SyncDB Data Dump

BCMSAI DataManager Dump [<file_name>]

Dump the SAI data manager to the console or, given a file name, to that file in the warm-boot state directory. On SONiC the console form prints only DM data can be found here: /var/warmboot/brcm_sai_dm_techsupport.tgz.: the dump goes to that archive inside the syncd container. An over-long name prints File name length cannot be more than <n>.

This is not read-only: every DataManager form first walks and saves the SAI module state. See the warning above.

Hardware-validated

drivshell> BCMSAI DataManager Dump
DM data can be found here: /var/warmboot/brcm_sai_dm_techsupport.tgz.

BCMSAI dump_eapp_config

Print the embedded-application configuration: embedded-apps-location, feature-names, file-name, app-version, compatible-silicon and compatible-cancun. This keyword must be typed in full (any case). On a SONiC Trident 3 switch no embedded applications are configured and it prints only an empty embedded-apps-location: line. Read-only.

BCMSAI ObjectState [Brief | Type <objtype>]

Dump the SAI object-tracking state: all objects with no argument, a brief form with Brief, or one object type. <objtype> is a SAI object-type name without the SAI_OBJECT_TYPE_ prefix, in any case: port selects SAI_OBJECT_TYPE_PORT. Read-only.

On a SONiC switch ObjectState Type PORT prints nothing. If it prints nothing for you, turn object tracking on with ObjectState Configure Enable (below).

Hardware-validated

drivshell> BCMSAI ObjectState Type PORT
BCMSAI ObjectState Configure <Enable | Disable | Clear>

Turn SAI object tracking on or off, or clear it. Config is accepted as an abbreviation of Configure. Changes SAI debug state.

Unvalidated

drivshell> BCMSAI ObjectState Config Enable

BCMSAI route [vrf-all | vrf <vr_id> | brief | client <id>] [v4 | v6] [client <id>]

Dump the SAI route table. The defaults are all VRFs, both address families and client 0.

The first word always selects the VRF: vrf <id> selects one VRF, brief selects the brief form, client <id> sets the client, and any other word (conventionally vrf-all) means all VRFs. Only the next word is checked for v4 or v6. So BCMSAI route v4 shows both families; use BCMSAI route vrf-all v4 to see only IPv4. Read-only.

BCMSAI TechSupport [Module <id> | File [<file_name>] [Append] | Append]

Collect SAI tech-support output. With no argument every enabled module is dumped; Module <id> dumps one module. File sets the output file name (File with no name resets it to sai-techsupport.log), and Append appends to the file instead of overwriting it. The full dump turns the shell console off and on again (console off / console on) while it writes the log file, and ends with SAI Timing: Techsupport took <s> seconds. Module IDs are listed by TechSupport Config; module 0 is SAI_API_INT_ERROR, which has nothing to dump and only prints its timing line.

BCMSAI clm port <id> <set enable <true | n> | set media <fiber | copper | backplane | none> | get delay | tx>
