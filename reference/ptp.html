PTP

PTP stack configuration

PTP

Configure the PTP (IEEE 1588) stack that runs as firmware on the switch’s embedded cores: stacks, clocks, ports, time sources, time-of-day input and output, servo, unicast masters and slaves, telecom profiles and debugging.

The first word selects the area and can be abbreviated to its capital letters. PTP <area> HELP prints the help of that area only (for example PTP Port HELP). An unknown word prints the usage. Most forms end by printing PASSED, FAILED or INVALID SYNTAX. Many forms take Stack=<id>, Clock=<num> or Port=<num> selectors, which default to 0.

The built-in help is incomplete. The shell also has the areas TsFifo and TsOffset, PTP Stack Destroy, and further keys in several areas; they are listed below.

SONiC does not use the SDK PTP stack. The PTP firmware runs as an embedded application on the embedded cores, which stay in reset until one is loaded; the SONiC image on the switches in this guide loads none (see MCSStatus and Embedded applications). Without the firmware, every form that talks to a PTP stack or clock fails:

  • ptp clock show, ptp port show, ptp todoffset get and similar print <function>() Error... (FCN RETURN= -16); -16 is the SDK’s “Feature unavailable”.

  • ptp servo show, ptp master show, ptp slave show, ptp peerdataset, ptp counters and ptp telecom slave show print nothing of their own.

  • ptp time get prints Time: 0.000000000 and ptp channels status prints Channel configuration NOT supported for the servo type.

Each of these is followed by the SAI front-end’s Failed to execute the diagnostic command. Error: Operation failed. The forms that only touch the shell’s own settings still work: the HELP forms, ptp debug, ptp log, ptp modular get, ptp ctdev options, ptp register and ptp diagshell options.

Safety: Show, Get, PeerDataset and HELP forms are read-only; every other form changes the PTP firmware state. PTP Stack Create and Destroy start and stop the firmware stack.

Assisted timing and external inputs

Assisted Partial Time Support (APTS) selects frequency and time/phase sources separately. On a platform that supports it, check both selected sources and their availability: receiving time-of-day data alone does not establish that the frequency input and 1PPS signal are usable. The external DPLL and board wiring are part of that setup.

A virtual PTP port participates in the best-master clock selection; it is not interchangeable with APTS’s additional frequency-input path. A working PTP stack or a recognised shell option is therefore insufficient to establish APTS support. Confirm the switch, firmware and board’s timing interfaces before applying an APTS configuration to Trident 3.
