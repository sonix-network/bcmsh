L3

Manage L3 (IP) addresses

L3

The L3 (routing) tables: router interfaces, egress objects (next hops), ECMP/multipath groups, host entries, IPv4 and IPv6 routes, tunnels, DSCP maps, the IPv6 prefix map and NAT.

A command is l3 <table> <sub-command> [Key=<value> …]. The table and sub-command words must be written out in full; case does not matter. l3 egress show and L3 EGRESS SHOW work, but l3 eg sh does not. destroy and delete mean the same thing everywhere. An unknown sub-command prints the usage. The Key=<value> arguments can be abbreviated as usual: the upper-case letters of a key are the ones you must type.

The built-in help differs from what the shell accepts in a few places:

  • l3 l3table untag is in the help, but prints the usage: there is no such sub-command.

  • l3 l3table sanity only prints Command only valid for XGS2 switches.

  • The help shows Gateway= for l3 defip add, but only l3 defip destroy accepts it.

  • Some keys are accepted but not shown: InnerVlan and NATrealm (l3 intf add), IPMC (route add), DSCPMap (l3 tunnel_init set), RemoteTerminate and TunnelID (l3 tunnel_term add), and TrieTree (l3 alpm show). The help spells InternelDebug; the key is InternalDebug.

  • l3 defipinfo (not in the help) does nothing on Trident 3.

  • l3 route test perf takes keys the help does not list; see l3 route test perf.

When an L3 call fails, the shell prints an L3: or ERROR L3: line with the SDK’s reason, followed by Failed to execute the diagnostic command. Error: Operation failed.; bcmcmd still exits 0.

What a SONiC switch shows: SONiC’s router interfaces (for example Vlan902) appear in l3 intf show with their VLAN and the switch MAC. Egress objects are numbered from 132768. Two of them carry most routes: one that sends to the CPU (INTF 16383), used by connected subnets and the switch’s own addresses, and one that drops, used by the default route until SONiC learns a real one. With ALPM off, routes are in the plain route TCAM shown by l3 defip show.

Commands that only show (show, info, find, hash, conflict) are safe on a running switch. SONiC’s own generate_dump runs l3 intf show, l3 egress show, l3 defip show, l3 l3table show, l3 ecmp egress show, l3 multipath show, l3 ip6host show and l3 ip6route show on Broadcom XGS switches (scripts/generate_dump (show techsupport collector)).

Warning

Every add, update, destroy/delete, clear, set, insert, remove and age changes the hardware behind SONiC’s back. SONiC is not told and its view goes stale. l3 init, l3 detach and l3 route test perf disrupt a running switch.

Other Broadcom-based systems use the same commands: Cisco Nexus 9000 Series NX-OS Troubleshooting Guide, Release 9.3(x) – Troubleshooting VLANs walks a VXLAN set-up through l3 egress show and l3 multipath show; FBOSS: BcmSwitch gatherSdkState/rcload, validated shell commands, diag shell stress test, vendor-diag-shell skill, debugging doc lists the l3 table dumps FBOSS collects for its SDK state; Edgecore AS5610-52X reverse engineering: Cumulus 2.5 baseline captures has l3 defip show and l3 l3table show output from a Trident+ switch; and Dell Networking OS10 Routes are Not Installed (KB 000322394) uses l3 info and l3 defip show to check route table capacity on a Trident 3-X7 switch.

l3 init

Initialise the L3 module. On a running SONiC switch this resets L3 state underneath syncd. Do not use it on a production switch.

Unvalidated

drivshell> l3 init
l3 detach

Detach the L3 module, removing all L3 state. Do not use it on a production switch.

Unvalidated

drivshell> l3 detach
l3 info

Show the size and use of the L3 tables (hosts, routes, next hops, ECMP groups) as <name> : <used> / <max> lines, plus two ECMP defragmentation counters. Safe. On Trident 3 with ALPM off there is room for 16384 hosts, 16384 routes, 65536 next hops and 4096 ECMP groups. Dell Networking OS10 Routes are Not Installed (KB 000322394) uses it on a Trident 3-X7 switch to find a full route table.

Hardware-validated

Delete an L3 interface. l3 intf delete is the same command. The interface must exist (see l3 intf show); otherwise the shell prints L3: Error (Entry not found) destroy interface (<id>). Changes the hardware behind SONiC’s back.

l3 multipath show [<entry>]

List the multipath (ECMP) egress objects, or one by ID. Safe. It prints nothing when there are none, as on a SONiC switch without ECMP routes. Cisco Nexus 9000 Series NX-OS Troubleshooting Guide, Release 9.3(x) – Troubleshooting VLANs shows l3 multipath show 200264 on a Nexus 9000.
