LED

Control/Load LED processor

LED

Control the front-panel LED program and its link-state feed. On Trident 3 the LED program runs as firmware on a Cortex-M0 core of the switch’s CPU management interface, the same core that runs the linkscan firmware (see M0).

An optional number before the sub-command selects the LED processor (led 0 stop); the default is 0, and an out-of-range number prints Invalid uProcessor number: <n>, set to 0 and uses 0. With no sub-command the command prints a status line. Sub-command words ignore case but cannot be abbreviated. Besides the forms in the built-in help, the shell also accepts setstatus and accustatus.

On SONiC the LED firmware is loaded at start-up with m0 load (the linkscan firmware at offset 0x0 and the board’s LED program at 0x3800), followed by led auto on and led start; see led.md (SONiC on Broadcom: LED debugging). Depending on the SAI release, led auto on prints nothing or - Using new linkscan_cb without port speed.

Safety: status, accustatus, dump and the bare command are read-only. start, stop, auto, setstatus, load and prog change what the front-panel LEDs show; the LEDs can stay dark or wrong until SONiC’s LED setup runs again. Forwarding is not affected.

LED state and port state

A front-panel LED combines hardware activity/link inputs, software link updates and the board’s custom LED program. A wrong colour or a dark LED can therefore occur even while the port forwards traffic.

Compare ps with LED accustatus and LED status, then use the bare LED command to check whether the firmware and automatic updates are enabled. Accumulation memory supplies inputs to the LED program; the displayed pattern is a separate result. The pattern’s colour and blink encoding depend on the board, so do not decode it as a generic link-state bitmask.

With an external PHY, the internal SerDes link and the cable-side link can also disagree. Software link updates let the LED program reflect the external link. Disabling automatic updates can leave its indication stale. Raw LED memory indices follow port-macro/subport order; do not substitute an LED memory index for a shell logical port number.

LED status

Print Port <n> led status 0x<x> for every port: the byte the LED program displays for that port. <n> is the logical port number shown in brackets by ps (ce0 is 1, xe0 is 9). What the bits mean is up to the board’s LED program; on a SONiC Seastone2 switch disabled ports read 0x3 and ports that are up 0x1 or 0x2, and the value of a busy port can change from one call to the next. If the LED firmware is stopped it first prints LED firmware is not running. Read-only.

LED setstatus <port> <value>

Set the LED status byte of one port. Both numbers may be given in decimal or 0x hex. Not in the built-in help. The next link change on the port overwrites the value while auto is on.

Unvalidated

drivshell> led setstatus 1 0x1
LED start

Start the LED firmware. Prints Error:Unable to start LED FW on failure.

Unvalidated

drivshell> led start
LED stop

Stop the LED firmware. The LEDs freeze or go dark.

Unvalidated

drivshell> led stop
LED auto [on | off]

Turn automatic LED updates on link changes on (the default) or off. Turning them on also refreshes the LED state of all ports once. Any other word prints the usage.

Unvalidated

drivshell> led auto on
LED load <file.hex>

Load an LED program from a text file of hex bytes. The firmware is stopped for the load and then put back in its previous state. If the firmware is running the shell may refuse with FW download is not allowed since LED Firmware is running.; run led stop first. On Trident 3, SONiC loads its LED program with M0 load instead.

Unvalidated

drivshell> led load /tmp/led.hex
LED prog <hexdata>

Load an LED program given inline as hex bytes. The firmware is stopped first. Errors are Program memory exceeded and Invalid character.

Unvalidated

drivshell> led 0 prog 86 FF 06 FF
LED dump

Print 256 bytes of the LED program memory as hex, 16 per line, each line prefixed with its address. On Trident 3 the dump starts at 1303800, the 0x3800 offset where SONiC loads the board’s LED program. Read-only.
