WARMBOOT

Optionally boot warm

WARMBOOT

Show and control the SDK’s warm-boot state. It can tell you whether the SDK came up warm or cold, show the warm-boot store (scache) and its history, and sync state to the store. It can also mark the units as warm-booting or shut the SDK down before a warm boot.

Under SONiC, the SAI and syncd own the warm-boot state; warm-reboot drives it. Only the display forms of this command are safe on a running switch.

All keywords must be typed in full. With no argument, or an unknown word, the command prints its help. The built-in help does not list scache, which the shell accepts.

Safety on a running switch

Sub-command

Effect

show, storage, usage, history, scache

Read-only.

sync

Writes the SDK’s state to scache now. Forwarding is not affected, but the stored image is replaced outside SONiC’s control.

storage alloc

Changes a module’s scache allocation.

on, off

Change the SDK’s warm-boot flag. See the warning under WARMBOOT on.

shutdown

Shuts the SDK down underneath syncd. See the warning under WARMBOOT shutdown.

Hardware-validated: Did the SDK come up warm or cold?

drivshell> warmboot show
Unit 0: Cold Boot
WARMBOOT show

Print Unit <n>: Warm Boot or Unit <n>: Cold Boot for every attached unit. Read-only.

Hardware-validated

drivshell> warmboot show
Unit 0: Cold Boot
WARMBOOT storage

Print the scache space each SDK module needs, under the heading Warmboot storage requirements:. Each line is 0x<id> <module>(<id>): <bytes>, and the list ends with Total storage required: <n> bytes. Without a configured store it prints External storage not configured!. Read-only. On a SONiC Trident 3 switch the store is configured and the total is about 87 MB, most of it (about 78 MB) for the field module.

WARMBOOT storage alloc <module_id> <scache_part_no> <alloc_size>

Grow one module’s scache allocation. All three values must be integers. Otherwise it prints Invalid module Id., Invalid scache part no. or Invalid scache alloc size.. The module IDs are those listed by warmboot storage. This changes warm-boot state.

Unvalidated: Replace <module_id> with an ID from “warmboot storage”

drivshell> warmboot storage alloc <module_id> 0 1024
WARMBOOT usage

Print the scache space each module currently uses, under the heading Warmboot storage usage:. Each line is <module>(<id>) module: <bytes> bytes handle: <handle>, and the list ends with Total storage usage: <n> bytes. Read-only. After a cold boot, before anything has been synced, every module shows 0 bytes and the total is 0.

WARMBOOT history [max | <n>]

Show the warm-boot history. It starts with Last SDK cold boot:, which gives the version, whether the scache CRC was checked, and the up time. Then come the latest <n> warm-boot records (3 by default, all with max). Each record lists the modules whose warm-boot version changed. An invalid argument prints Invalid options for warmboot. or Invalid input for record number. Without history it prints Warmboot history is not available!. Read-only. A switch that has only cold-booted shows just the Last SDK cold boot: block ([ OK ] <sdk version> (<build date>), Scache CRC: NO, Up Time: <date>) and no records.

Hardware-validated

drivshell> warmboot history max

Last SDK cold boot:
-----------------------------------------------------
    [ OK ] sdk-6.5.35-SP1 (Wed Sep 30 11:49:47 2026)
    Scache CRC: NO
    Up Time: Mon Oct 26 11:49:49 2026
WARMBOOT scache [<handle>]

Dump the scache state or, given an integer handle, one scache handle. Read-only. The dump starts with the block checks and scache info, then a table of every handle (about 80 on a SONiC Trident 3 switch) with its offset, size, used bytes, host addresses and flags.

WARMBOOT sync

Print syncing state to WB external storage. and write the SDK’s warm-boot state to scache now. Failure prints bcm_switch_control_set failed.. It always acts on unit 0.

Unvalidated

drivshell> warmboot sync
WARMBOOT on

Mark every unit as warm-booting.

Warning

Do not use this on a running SONiC switch. While the flag is set, the SDK treats later API calls as warm-boot recovery and skips many hardware writes. Configuration from syncd then silently stops reaching the switch.

Unvalidated

drivshell> warmboot on
WARMBOOT off

Clear the warm-boot flag on every unit, as the SDK does at the end of warm-boot recovery. This changes SDK state.

Unvalidated

drivshell> warmboot off
WARMBOOT shutdown

Shut the SDK down cleanly ahead of a warm boot. This stops linkscan, cleans up packet transmit, and shuts down the BCM and SoC layers. It prints bcm/soc shut down on unit <n>.

Warning

This removes the SDK from underneath syncd. Forwarding state and syncd’s access to the switch are lost, and syncd and the switch will need a restart. Never run it on a production switch.

Unvalidated

drivshell> warmboot shutdown

Built-in help

Parameters: [on | off | show | shutdown | storage [alloc <module_id> <scache_part_no> <alloc size>]| sync | usage | history]
Signal warm/cold boot or display current boot status
or shut down software components before a warm boot
or display the warmboot external storage requirements
or show actual current module compressed usage (XGS/XCORE only)
or allocate additional scache for given module and part no.
or display the warmboot history (XGS only)
