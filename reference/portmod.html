PortMod

Portmod Diagnostics

PortMod

Shortest form: pm.

PortMod (port module) diagnostics for the layer that drives the MAC and SerDes of each Port Macro (PM). Use it to see how logical ports map to Port Macros, SerDes cores and physical lanes, to read link, auto-negotiation and flow-control state, and to run PRBS and eye scans on a lane.

Sub-command names must be typed in full: portmod info works, portmod inf does not. An unknown or missing sub-command prints the full usage. When a sub-command is missing required arguments it prints its own short usage (a command: and example: block) and fails.

Arguments are key=value pairs. port=<n> is the logical port number, not a port name: write port=1, not port=xe0. Use show pmap or portmod info port to find the numbers. A number that is not a port of the unit prints ERROR: Port <n> is not valid for unit <unit>.

usage, info, status, fc, autoneg, core, phy and regdump only read state. On a SONiC Trident 3 switch info, fc and autoneg give full answers; status, core, phy and regdump are partly or wholly unimplemented for the Trident 3 SerDes driver (details under each sub-command). prbs set stops traffic on the port; prbs get and eyescan keep the shell busy while they run.

Hardware-validated

portmod info pm

Show which ports are mapped to which port macros, SerDes cores and physical lanes. The table has the columns PM id, type, phys and logic ports: one row per Port Macro with its core type, physical lane range and attached logical ports (or no port attached). Read-only.

Details of one Port Macro or one port. For a Port Macro: PM ID, PM Type, Phys, Logical Ports Attached and the TX/RX lane maps. For a port: Port, Parent PM, Phys, Mac, the TX/RX polarity, the internal and external PHY addresses and Core Mode. If both keys are given, port is used. Read-only.

portmod core port=<port_id>

Show the SerDes core that serves the port: its temperature, PLL range, firmware version and firmware CRC, each on a line such as Port<n>(<name>): Core temperature is <n>. Read-only. On a Trident 3 the temperature (°C) and PLL range are real, but the firmware version and CRC read -1: the Falcon driver does not report them here. The microcode version is shown by dsc of phy diag (UCODE_VER).

portmod phy port=<port_id> [phychain=<n>] [lane=<n>] [if=<sys | line>]

Dump the receive and transmit diagnostics of one SerDes lane as PHY <field>: <n> lines: signal detect, receive lock, PPM offsets, PMD and OSR mode, VGA, DFE taps, slicer offsets, the eye margins measured by the SerDes firmware, the transmit FIR taps and more. phychain selects the PHY in the chain (default: the outermost one), lane defaults to 0, and if selects the system or line side of an external PHY; any other if value prints InterFace must be sys or line. The built-in help shows only port; the shell actually accepts all four keys. Read-only.

portmod prbs set port=<port_id> [mode=<phy | mac>] [polynomial=<n>] [invert=<bool>]

Start the PRBS generator and checker on the port.

  • The built-in help shows Loopback=<true|false>; the shell actually rejects it with ERROR: invalid option.

  • mode=si or mode=mac selects MAC/PCS PRBS. Any other value, and no mode at all, selects SerDes PRBS.

  • Only polynomial values 0 to 6 are distinct; larger values wrap around modulo 7.

Turn linkscan off for the port first, or linkscan may re-initialise the SerDes and the checker will not lock (PRBS testing on Broadcom (SONiC) — prbs_broadcom.md + README, written for other Broadcom chips).

Warning

The port carries no traffic while PRBS runs. SONiC is not told.

Unvalidated

drivshell> portmod prbs set port=1 mode=phy
portmod prbs get port=<port_id> [mode=<phy | mac>] [interval=<sec>]

Wait interval seconds (default 0), then read the checker and print Port<n>(<name>): PRBS is [not ]currently locked!, Port<n>(<name>): PRBS is [not ]unlocked since last call! and Port<n>(<name>): PRBS has <n> errors count!. Use the same mode as for set. Read-only; the shell is busy during the wait.

Unvalidated

drivshell> portmod prbs get port=1 interval=10
portmod prbs clear port=<port_id> [mode=<phy | mac>]

Turn the PRBS generator and checker off, so the port can carry traffic again. This changes SerDes state.

Unvalidated

drivshell> portmod prbs clear port=1
portmod eyescan port=<port> mode=<mode> lane=<lane>

Measure and print an eye diagram for one SerDes lane. The full set of options is port, ber, vertical_max, vertical_min, vertical_step, horizontal_max, horizontal_min, horizontal_step, sample_time, lane, unit, mode and if. mode is fast or lowBER; anything else prints Mode must be fast or lowBER. if is sys or line, and unit selects the PHY in the chain. The built-in help does not show unit. sys_lane_mask is refused with a message to use if=sys lane=<lane> instead. The shell is busy while the scan runs, and the scan may disturb traffic on the lane.

Unvalidated: First lane of logical port 5

portmod regdump port=<port_id>

Dump all SerDes registers of the port’s lanes, for the internal PHY and for an external PHY if there is one. Without port it prints ERROR: please input port ID: port=<id>. Read-only. On a SONiC Trident 3 switch it fails for the internal SerDes with ERROR: phy status dump Feature unavailable and ERROR: Getting phy status failed: Internal error, followed by the SAI front-end’s Failed to execute the diagnostic command.
